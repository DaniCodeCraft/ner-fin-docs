Ключевые решения
1. Единая токенизация для обучения и инференса
Проблема. Классический text.split() даёт токены, где пунктуация приклеена
к словам:

'АО "Дельта", в лице'  →  ['АО', '"Дельта",', 'в', 'лице']

Токен '"Дельта",' включает запятую. Если BIO-разметка ставит I-ORG на этот
токен, запятая попадает в сущность.

Решение. Отдельная регулярка, где пунктуация — самостоятельные токены.

Синхронизация. _tokenize определена в двух файлах:
src/generation/build_dataset.py и src/models/predict.py — с идентичной
регуляркой. Проверка: python -m scripts.test_tokenizer.

2. Word boundaries в _collect
Проблема. Наивный text.find(value) найдёт сущность внутри более длинного
токена. Например, Ромашка найдётся внутри Ромашка",.

Решение. Проверка границ слова — символ перед start и после end
не должен быть буквой/цифрой.

3. Offsets в dataset.jsonl
Проблема. Восстановить исходное форматирование из токенов невозможно.
1269 может быть 1 269 (MONEY) или 1269 (номер).

Решение. Каждый токен хранится как [token, label, start, end]. Любой
потребитель берёт text[start:end] и видит ровно исходный текст.

Проверка: python -m scripts.check_dataset.

4. Валидация реквизитов по контрольным суммам
Проблема. Модель может ошибиться и предсказать INN на случайной
последовательности цифр.

Решение. На инференсе каждый спан проходит проверку на валидность
(ИНН, ОГРН, БИК). Если валидатор не проходит — спан удаляется.

Модель

Input: subword-токены (WordPiece rubert-tiny2)
   │
   ▼
rubert-tiny2 encoder
   2 слоя, hidden=312, 83828 vocab, max_position=512, 29M params
   │
   ▼  hidden_states [B, T, 312]
Linear(312 → 21)
   │
   ▼  logits [B, T, 21]
CrossEntropyLoss(ignore_index=-100)

Почему rubert-tiny2, а не rubert-base
Модель	Params	RAM	Inference (CPU)
cointegrated/rubert-tiny2	29M	120 МБ	~80 мс
DeepPavlov/rubert-base-cased	178M	~700 МБ	~500 мс
ai-forever/ruBert-base	180M	~700 МБ	~500 мс
На шаблонных данных большая модель не даёт прироста F1, но в 6× медленнее.

Что мы решили НЕ делать
Альтернатива	Почему нет
CRF-слой поверх BERT	Прирост ~0.3% не оправдывает потерю HF-совместимости
Дообучение rubert-base	+5× params, +6× времени, ноль прироста
Rule-based NER	Не работает на ORG/PERSON с вариативным написанием
LLM через API	Нужен интернет, платно, задержка 500+ мс
Коммитить модель в git	116 МБ — не для git; публикуем на HF Hub
