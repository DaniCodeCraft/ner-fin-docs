## Три шаблона документов

### 1. Платёжное поручение

```
ПЛАТЁЖНОЕ ПОРУЧЕНИЕ № {contract} от {date}
Плательщик: {payer}
ИНН {inn1}, КПП {kpp1}, ОГРН {ogrn1}
Р/с {acc1} в банке, БИК {bik}
Получатель: {receiver}
ИНН {inn2}, КПП {kpp2}
Р/с {acc2}
Сумма: {amount}
Назначение платежа: оплата по договору № {contract}.
Главный бухгалтер: {person}
```

**Сущности (14):** `CONTRACT`, `DATE` ×2, `ORG` ×2, `INN` ×2, `KPP` ×2, `OGRN`, `ACCOUNT` ×2, `BIK`, `MONEY`, `PERSON`.

**Особенность:** `CONTRACT` встречается дважды — в шапке и в назначении.

---

### 2. Договор оказания услуг

```
ДОГОВОР № {contract}
г. Москва                                {date}

{org1}, в лице {person1}, именуемое «Исполнитель»,
и {org2}, в лице {person2}, именуемое «Заказчик»,
заключили настоящий договор о нижеследующем:
1. Стоимость услуг составляет {amount}.
2. Оплата производится на р/с {acc}, БИК {bik}.
3. ИНН Исполнителя: {inn}.
```

**Сущности (10):** `CONTRACT`, `DATE`, `ORG` ×2, `PERSON` ×2, `MONEY`, `ACCOUNT`, `BIK`, `INN`.

**Особенность:** после `{org1}` и `{person1}` идут запятые — классический кейс, где `text.split()` ломает разметку.

---

### 3. Счёт на оплату

```
СЧЁТ НА ОПЛАТУ № {contract} от {date}
Поставщик: {supplier}
ИНН/КПП: {inn1}/{kpp}
Банк: ПАО Сбербанк, БИК {bik}
Р/с: {acc}
Покупатель: {buyer}
ИНН покупателя: {inn2}
Итого к оплате: {amount}
Руководитель: {person}
```

**Сущности (10):** `DATE`, `ORG` ×2, `INN` ×2, `KPP`, `BIK`, `ACCOUNT`, `MONEY`, `PERSON`.

**Особенность:** `ИНН/КПП: 2181960010/428714227` — слэш разделяет два реквизита. Без правильной токенизации модель склеит их в одну сущность.

## Генераторы значений

Все реквизиты генерируются **с валидными контрольными суммами** — они проходят проверки по алгоритмам ФНС.

### ИНН (10 или 12 знаков)

```python
def gen_inn() -> str:
    length = random.choice([10, 12])
    if length == 10:
        digits = [random.randint(0, 9) for _ in range(9)]
        weights = [2, 4, 10, 3, 5, 9, 4, 6, 8]
        check = sum(d * w for d, w in zip(digits, weights)) % 11 % 10
        return "".join(map(str, digits)) + str(check)
```

### ОГРН (13 или 15 знаков)

```python
def gen_ogrn() -> str:
    length = random.choice([13, 15])
    body = "".join(random.choices("0123456789", k=length - 1))
    div = 11 if length == 13 else 13
    check = int(body) % div % 10
    return body + str(check)
```

### БИК (9 знаков)

```python
def gen_bik() -> str:
    return "04" + "".join(random.choices("0123456789", k=7))
```

Все БИК начинаются с `04` — обязательный префикс российских БИК.

## Формат `dataset.jsonl`

Каждая строка — JSON. Формат токена: `[token, BIO-label, start, end]`.

```json
{
  "id": 0,
  "text": "СЧЁТ НА ОПЛАТУ № 2678-2023 от 2022-10-30\n...",
  "tokens": [
    ["СЧЁТ", "O", 0, 4],
    ["НА", "O", 5, 7],
    ["ОПЛАТУ", "O", 8, 14],
    ["№", "O", 15, 16],
    ["2678", "B-CONTRACT", 17, 21],
    ["-", "I-CONTRACT", 21, 22],
    ["2023", "I-CONTRACT", 22, 26],
    ["от", "O", 27, 29],
    ["2022", "B-DATE", 30, 34],
    ["-", "I-DATE", 34, 35],
    ["10", "I-DATE", 35, 37],
    ["-", "I-DATE", 37, 38],
    ["30", "I-DATE", 38, 40]
  ]
}
```

Offsets позволяют восстановить **точный** фрагмент текста через `text[start:end]` — без эвристик склейки. Проверка: `python -m scripts.check_dataset`.

## Как перегенерировать

```bash
Remove-Item -Recurse -Force data/raw, data/processed
python -m src.generation.build_dataset
python -m scripts.check_dataset
python -m scripts.test_tokenizer
```

**Важно:** после изменения `templates.py` или `generators.py` — обязательно перегенерировать датасет и **переобучить модель**. Иначе старые веса не будут соответствовать новым данным.

## Ограничения данных

- **Шаблонность.** Все документы из 3 фиксированных шаблонов.
- **Нет шума.** Чистые строки, стандартные кавычки, корректные разделители.
- **Ограниченный словарь.** ~14 названий организаций, Faker-ФИО, 4 валюты.
- **Нет OCR-ошибок.** Текст синтетический — без `О` vs `0`, `I` vs `1`.
