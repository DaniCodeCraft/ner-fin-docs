# Ограничения и что дальше

Честный разбор: что работает, что не работает, где границы применимости.

---

## Метрики — контекст

| Что измерено                   | Значение  | Насколько верить        |
| ------------------------------ | --------- | ----------------------- |
| F1 на синтетическом тесте      | 1.0000    | Модель учится правильно |
| Score на train-документах      | 0.93–0.99 | Работает                |
| Score на коротких фразах (OOD) | 0.3–0.6   | Ограничение данных      |
| Ожидаемый F1 на реальных PDF   | 0.85–0.92 | Оценка                  |

**F1 = 1.0 — не достижение, а артефакт.** Синтетические данные без шума + 5 эпох
обучения = модель заучивает шаблон. На реальных данных будет честнее и ниже.

---

## Ограничение 1 — шаблонность данных

Модель обучена на 3 шаблонах. Она не видела:

- Банковские выписки (транзакции, дебет/кредит, остатки).
- Акты выполненных работ.
- Накладные / счёта-фактуры (УПД).
- Инвойсы на английском или смешанные.
- Письма / претензии с реквизитами в теле.

**Что делать:** добавить шаблоны в `src/generation/templates.py`.
Перегенерировать данные. Переобучить.

## Ограничение 2 — нет шума

Синтетика слишком чистая:

| Проблема в реальных документах | Что упущено                                  |
| ------------------------------ | -------------------------------------------- |
| Разные кавычки                 | `"Ромашка"`, `«Ромашка»`, `'Ромашка'`        |
| Опечатки в реквизитах          | `ИН:` вместо `ИНН:`, `ОО0` вместо `ООО`      |
| Разные форматы дат             | `01.01.2024`, `1 января 2024`, `2024-01-01`  |
| Разные форматы сумм            | `100 000 руб.`, `100 тыс. руб.`, `сто тысяч` |
| Доп. пробелы                   | `ООО  "Ромашка"` (двойной пробел)            |
| Перенос строки в середине      | `ООО "Ромаш-\nка"`                           |
| OCR-ошибки                     | `О` ↔ `0`, `З` ↔ `3`, `l` ↔ `1`              |

**Что делать:** добавить шумовый слой в `build_dataset.py`. Применить к
`doc.text` до `_collect`. F1 упадёт до 0.95 на синтетике, но на реальных данных
вырастет до 0.92.

## Ограничение 3 — OOD-текст

**Пример:**

```
Вход:  'ООО "Ромашка", ИНН 7707083893, сумма 100 руб.'
Выход: ORG   | 'ООО "Ромашка"'   | 0.98 OK
       MONEY | '100 руб.'        | 0.54 низкий
       INN   | (не найден)
```

**Почему.** В обучении модель видела `ИНН/КПП: 2181960010/428714227` или
`ИНН покупателя: 3890838631` — с контекстом. В тесте — `ИНН 7707083893`
без префикса `ИНН:`. Модель не уверена.

**Что делать:**

1. Добавить короткие фразы в генератор: `'ИНН: 7707083893'`,
   `'ИНН организации — 7707083893'`.
2. Или regex-fallback на инференсе: `r'ИНН[:\s]+(\d{10,12})'`.

## Ограничение 4 — нет OCR

Сканы PDF / фото документов не обрабатываются. `pdfplumber` извлекает
**текстовый слой** — если он есть. Для сканов нужен:

- `pytesseract` — обёртка над Tesseract.
- `easyocr` — современный, лучше на русском, но тяжелее.

```python
# src/ingestion/ocr.py
import easyocr

_reader = easyocr.Reader(["ru"], gpu=False)

def load_scanned_pdf(path):
    import pdf2image
    images = pdf2image.convert_from_path(path, dpi=300)
    parts = []
    for img in images:
        result = _reader.readtext(np.array(img), detail=0, paragraph=True)
        parts.append("\n".join(result))
    return "\n\n".join(parts)
```

## Ограничение 5 — домен замкнут

Модель работает только на финансовых документах 3 типов. На других доменах
(медицина, юриспруденция, IT) — плохой F1.

**Что делать:** дообучить на целевом домене, либо использовать универсальные
NER-модели (`DeepPavlov/rubert-base-cased-conversational`) + fine-tune.

## Roadmap

### Приоритет 1 — быстрые улучшения

- [ ] Шум в генераторе — опечатки, разные кавычки, форматы
- [ ] Больше шаблонов — банковская выписка, акт, УПД
- [ ] Короткие фразы как отдельные документы
- [ ] Precision/recall графики — confusion matrix

### Приоритет 2 — production

- [ ] ONNX-экспорт (`onnxruntime`, 2–3× быстрее CPU)
- [ ] int8-квантизация (30 МБ вместо 116 МБ)
- [ ] Батчевый инференс — API принимает список текстов
- [ ] Кеш предсказаний (Redis / LRU)
- [ ] Метрики в проде (Prometheus + Grafana)

### Приоритет 3 — nice-to-have

- [ ] Active learning — CLI для правки предсказаний
- [ ] PDF report с подсветкой
- [ ] CoNLL-2003 export
- [ ] Multilingual
- [ ] Few-shot адаптация

## Что НЕ планируется

| Задача                          | Почему нет                                    |
| ------------------------------- | --------------------------------------------- |
| Заменить BERT на LLM            | Дороже, медленнее, нет интернета в проде      |
| Обучение с нуля                 | Синтетики мало, нужно 100k+ реальных примеров |
| Кросс-доменный NER              | Другая задача, другая модель                  |
| Публикация в открытые бенчмарки | Только синтетика — нечестное сравнение        |
